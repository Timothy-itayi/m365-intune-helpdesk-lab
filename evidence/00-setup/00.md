# osTicket Lab Setup

This osTicket lab was added to my existing **Operations Lab** project so I could reuse it for IT support practice.

## Stack

- Docker Compose
- osTicket
- MariaDB

## Setup

osTicket and MariaDB run as separate containers.

osTicket connects to MariaDB using the Docker service name:

```yaml
OST_DBHOST: mariadb
OST_DBNAME: osticket
OST_DBUSER: osticket
OST_DBPASS: ${OST_DB_PASSWORD}
```

MariaDB uses the same database credentials:

```yaml
MARIADB_DATABASE: osticket
MARIADB_USER: osticket
MARIADB_PASSWORD: ${OST_DB_PASSWORD}
```

Persistent volumes are used for:

```text
osticket-db
osticket-attachments
```

## Running the Lab

Start:

```bash
docker compose up -d
```

Check status:

```bash
docker compose ps
```

View logs:

```bash
docker compose logs -f
```

Open osTicket:

```text
http://localhost:8080
```

Stop:

```bash
docker compose down
```

## MariaDB Authentication Issue

When setting up the project again, osTicket could not authenticate with MariaDB.

The MariaDB logs showed:

```text
Access denied for user 'osticket'
```

The containers could communicate successfully, which confirmed the problem was authentication rather than networking.

The existing MariaDB volume had been created during the previous setup and contained the old database credentials.

The MariaDB root account had also originally been configured with:

```yaml
MARIADB_RANDOM_ROOT_PASSWORD: "yes"
```

I had not kept the generated root password, so I could not log in as root to reset the `osticket` database user.

Because the database only contained lab data, I recreated the MariaDB volume so it could initialise again using the current `OST_DB_PASSWORD`.

The full troubleshooting process is documented in [00-setup.md](../../docs/incidents/00-setup.md) in the `incidents` folder. The decisions made are in [00.md](../../docs/decisions/00.md).
